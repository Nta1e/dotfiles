## Conventions crewmates must follow
- Testing policy (captain AGENTS.md, 2026-09-27; every crewmate brief must carry it): never write unit tests after writing the code. Tautological and change-detector tests are harmful: do not add them. Do not add a regression test for a bug fix unless it closes a genuine gap in behavior coverage. Strongly prefer E2E tests as the sole testing mechanism, and use them to prove complex features work; every E2E run must end in a verifiable, repeatable artifact (for mobile UI: the Android screenshots plus the exact command that reproduces them) linked in the PR. When a unit must be tested in isolation, FIRST write down every way it could fail, THEN write the code. Bug fixes start by reproducing the bug end to end, as close to the user experience as possible.
- Commit messages: short, gitmoji-prefixed subject, terse body only when needed. Never add agent trailers (no Co-Authored-By, no Claude-Session, no "Generated with", no "Made with Cursor"). Standing source: `~/dotfiles/home/AGENTS.md` (also loaded by pi via `~/.pi/agent/AGENTS.md`). Cursor attribution is disabled in `~/.cursor/cli-config.json`; a commit-msg hook strips trailers in the krunchix repo. On 2026-09-23 Krunchix main was force-rewritten to `50c4aea` to strip Cursor trailers from #157/#158; any branch still based on `907b7f6`/`4c54d54`/`0a34b0a` must `rebase --onto origin/main`.
- PR titles must be the same gitmoji-prefixed style as commits (e.g. `🐛 Fix ...`, `🔧 ...`, `✨ ...`, `📝 ...`), never a conventional-commit `type(scope):` prefix - merging squashes the PR title into main's commit history, so a wrongly-styled title becomes a wrongly-styled commit. Every krunchix ship brief must tell the worker to check the title right after `gh pr create` and retitle it with `gh pr edit` if needed.
- PR descriptions are developer-facing release notes: state what changed, why it changed when useful, and how it was verified. Do not address or refer to the captain, include nautical/chat language, or add AI/agent attribution such as "Built with Claude".
- Never use the em dash "—" in text or code comments; use "-".
- Only comment code when it adds non-obvious value (why, gotcha, invariant).
- Never hand-edit CHANGELOG.md or files marked auto-generated.

- Boot the Android emulator ONLY with `~/Library/Android/sdk/emulator/emulator -avd kx34 -no-window -gpu host -no-audio -no-boot-anim` (quick-boots from the saved snapshot in about 10s; wait with `adb wait-for-device` then poll `adb shell getprop sys.boot_completed` for 1). Reuse an already-running kx34 instead of starting a second instance, and never kill it while another worker is capturing. `adb reverse tcp:8081 tcp:8081` connects the dev build to Metro. Record `adb logcat -d -b events | grep am_anr` with the screenshots; a non-empty result means the evidence is invalid.
- UI regression rule (captain, 2026-09-27): a UI task must not regress other components. Before opening the PR the worker runs the whole `packages/ui` test suite and the workspace typecheck, not only the tests it touched. When the change touches a shared primitive, token, theme or provider, the worker also finds every gallery component that consumes it, captures Android light/dark screenshots of each before (on `origin/main`) and after the change, and compares them. List the checked components and any intended visual changes in the PR body; an unintended difference blocks the PR until fixed.
